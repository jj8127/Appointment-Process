공통 가입은 이름·인증한 휴대폰·비밀번호·필수 동의와 선택 추천 코드만 받는다. 서비스 정보는 신청 단계에서 받는다. 2026-10-12 사용자 지시로 미정인 관심 등록 버튼·신청 폼·취소 화면을 제거했다. 가족간병·보험 상담·통신·렌탈·자동차 및 공통 이용내역은 준비 상태를 표시한다. 과거 신청 링크와 가입 완료는 서비스 안내로 돌아간다. 간병 안내는 기존 공개 홍보 페이지를 개인정보·추천 query 없이 열고, 간병업체 소속·등록을 요구하는 보험의 등록 조건을 안내한다. 아래 신청·정산 서버 계약은 아직 배포하지 않은 개발 기록이며 UI에서 관심 등록 API를 호출하지 않는다.

## 계정과 권한

- 공통 소비자 토큰의 kind는 `platform_member_session`이다. `platform-service`만 받는다. 기존 FC·GaramLink 검증은 이 토큰을 거부한다.
- 모바일의 기존 `role`은 `admin | fc | null`을 유지한다. 소비자는 별도 `platformMember`와 보안 저장소 token으로 로그인하며 FC 권한이 생기지 않는다.
- 공통 로그인에서 기존 FC·관리자 비밀번호는 기존 로그인 함수를 통과한다. 반환된 `insuranceSession`을 기존 설치 함수로 반영하므로 보험 권한·bridge token을 유지한다.
- 일반 회원 복원과 조회는 서버 검증을 거친다. 잠깐의 연결 실패는 이전 자료를 유지하고,401/403은 해당 자료를 숨긴다. 사용자가 다시 로그인할 수 있다. 늦은 응답은 다른 계정 자료를 덮지 않는다.
- 관리자 기능은 현재 활성 `staff_type=admin`을 서버에서 매번 확인한다. 본부장의 보험 업무 읽기 권한과 개인 생활 서비스 계정은 별개다. 개발자·본부장은 제휴·정산 관리자가 아니다.

## 추천 관계

2026-10-14 로컬 가족간병 초대: 가입 화면은 검증한 `code` query를 우선 입력하고 보험 pending이 아닌 care pending만 한 번 소비한다. 명시 code가 있으면 오래된 pending을 폐기하며 직접 수정·계정 변경·이미 가입한 회원에게 지연 결과를 적용하지 않는다. 신규 가입의 기존 서버 검증으로 추천 관계를 연결한다. 기존 회원의 추천인 변경·제휴 정산·탈퇴 시 승계 정책은 이 초대 UI에서 구현하거나 변경하지 않는다. 복사 주소와 공유 문구에는 개인 추천 코드만 있으며 이름·전화번호·세션은 넣지 않는다. 설치 후에는 원래 링크 다시 열기/코드 입력이 필요할 수 있다.

`platform_members.referrer_id` 하나를 모든 생활 제휴 서비스에 사용한다. 기존 FC는 최초 연결 시 기존 추천 관계를 가져온다. 공통 가입을 먼저 한 회원의 추천인은 나중에 FC가 되어도 덮어쓰지 않는다. 이후 보험 모집 관계 변경은 기존 증원수당 업무 계약에 따르며 공통 제휴 추천인을 자동 변경하지 않는다. 기존 보험 증원수당 명세와 제휴 혜택을 합산하지 않는다.

신청은 직접 추천인 UUID를 보존한다. 정산은 해당 UUID와 소비자·직접 추천인 비율 및 계산 기준을 보존한다. 상위 계보 전체에 수수료를 지급하지 않는다. 제휴사 설정 변경이 이전 정산을 다시 계산하지 않는다.

## 정산과 지급

제휴사마다 비율과 `referrerBasis`를 설정한다. 소비자 혜택은 수수료 총액 기준이며, 추천인 비율은 총액 또는 소비자 혜택을 뺀 나머지 기준을 명시한다. 원 미만은 버린다. 수수료50만 원·소비자50%·나머지의 추천인10%라면25만 원과2만5천 원이다. 이 예시는 운영 비율을 확정하지 않는다.

관리자는 실제 외부 거래 번호와 제휴사 정산 증빙을 확인한 뒤 완료 시각을 기록한다. 지급 기한은 완료 시각+7일이다. 동일 신청에 정산을 중복 생성할 수 없다. 설정 수정은 revision을 비교하며 같은 요청 재시도는 기존 결과를 반환한다. 실제 은행 이체는 실행하지 않는다. 이체 완료 후 지급 시각·이체 번호를 기록하는 `mark_paid`만 제공한다.

관심 등록은 본인만 정산 전에 취소할 수 있다. 확정 정산의 취소·환불은 별도 대조가 필요하여 일괄 삭제하지 않는다. 각 조회는 최신100건으로 제한되며 누적 총액으로 표시하지 않는다.

## 병원과 보험

2026-10-12 로컬 시험: 사용자가 가상 데이터를 요청하여 `EXPO_PUBLIC_HOSPITAL_DEMO=true`인 설치본에서만 서울·경기·부산·대전의 가상 병원12곳을 표시한다. 기존 목록·진료과·지역/구·검색·상세 UI와 응답 스키마를 재사용하며 기존 가상 사진3개를 앱에 포함한다. 화면 제목에 샘플을 표시한다. 전화/홈페이지는 제공하지 않고 가상 주소 길찾기는 비활성화한다. 병원 측정 요청도 로컬에서만 완료하며 운영 광고 집계에 보내지 않는다. 플래그가 없으면 기존 서버 API를 사용하고 실제 광고 계약만 표시한다. 플래그는 로컬 APK 빌더에만 설정하며 저장소 `.env`와 운영 DB/함수는 변경하지 않는다.

revision-15(2026-10-11): 제휴병원 홈은 빈 검색 조건으로 처음부터 조회한다. 검색 전에는 등록된 진료과 최대6개와 전체 보기, 사진 중심의 가로 소개 카드, 전체 기본 목록을 보여준다. 시·도/시·군·구 선택은 소개와 목록 모두에 적용한다. 병원명·진료과 검색 중에는 결과 목록에 집중하며 검색 초기화는 선택한 지역을 유지한다. 소개 병원도 기본 목록에서 제외하지 않는다. 실제 계약 자료가 없는 상태는 빈 목록으로 표시하고 가상의 병원을 제품에 채우지 않는다.

병원 검색 목록은 키보드를 드래그로 닫지 않고 보고된 키보드 높이를 목록 아래 스크롤 여유로 더한다. 공통 로그인·가입은 기존 `KeyboardAwareWrapper`가 입력 이동을 맡는다. 제휴·정산 관리의 병원 계약·성과 입력 컴포넌트는 별도 세로 스크롤을 만들지 않으며, 상위 관리 화면이 보고된 키보드 높이를 콘텐츠 아래 여유로 더해 하나의 스크롤 소유권을 유지한다. 이 소유권은 `scripts/audit/mobile-keyboard-surfaces.json`에서 직접 화면과 공유 입력 섹션을 함께 추적한다.

병원 화면은 서비스 탐색과 정보에 집중한다. 반복 면책·경고 문구는 표시하지 않으며 광고 배지, 정보 확인일, 실제 오류/이전 조회 상태, 관리자 승인 입력과 기능 조건을 유지한다.

병원은 광고 기간·노출 위치·광고비와 구조화된 시·도 코드/시·군·구를 설정한다. 공개 지역 목록에서 선택한 지역, 병원명과 진료 분야로 검색한다. 목록은 페이지 단위로 불러오며 강조 지면과 일반 목록 모두 광고임을 표시한다. 상세는 사진·소개·주소·전화·홈페이지·운영시간·정보 확인일을 제공한다. 전화와 길찾기는 기존 외부 URL helper를 사용한다. 비회원도 조회하며 스택으로 돌아올 때 검색과 목록 위치를 유지한다.

한국 날짜에 유효한 활성 계약이고 병원이 정보/사진/문구를 승인했으며 운영자가 심의 필요 여부를 확정한 자료만 공개한다. 심의 필요 계약에는 승인 번호와 유효 종료일이 필요하다. 번호가 없거나 만료되면 노출하지 않는다. 이 기록은 운영자의 확인이며 앱의 법적 심의 판정이 아니다. 강조 지면 후보는 서버의 15분 구간에 따라 최대5개를 다시 선택하며 나머지 계약도 페이지 목록에 남는다. 노출 수 보장이나 조회 중인 화면의15분 자동 갱신을 약속하지 않는다. 실제 제휴 자료가 없어 초기 목록은 비어 있다. 참고 사이트의 병원을 실제 제휴로 복제하지 않는다.

`record_hospital_event`는 짧게 유효한 서명된 게시 영수증과 익명 세션/이벤트 UUID를 사용한다. 화면이 활성 상태에서 일정 시간 보인 광고와 상세 열람, 전화/길찾기 버튼 클릭만 기록한다. 이벤트 재전송과 세션별 반복을 제한하며 계약 revision·실제 노출 지면·한국 날짜를 보존한다. 원시 이벤트 테이블은 service-role만 접근한다. 집계는 활성 관리자만 `get_hospital_report`에서 기간·병원별로 확인한다. 이는 익명 클라이언트 신호이며 실제 통화 완료·내원·진료 매출의 증거가 아니다.

현재 보고서는 오늘 기준90일 전까지의 이벤트를 집계하고 한 요청의 기간은 최대93일, 집계 행은5000개로 제한한다. 더 큰 범위는 기간/병원 조건을 줄이도록 안내한다. 오래된 이벤트의 삭제는 정상 이벤트 수집 시 실행하며 고정 일정의 삭제 작업은 아직 없다. 정기 정리 운영과 실제 서버 수집은 출시 전에 확인한다.

병원 방문·소개 혜택은 생성하지 않는다. 보험 상담 서비스는 준비 중이며 기존 보험 수당 업무를 유지한다. 광고비·고객 연락처·환자 정보는 공개 응답과 성과 보고에 포함하지 않는다.

## 개인정보와 배포 경계

신규 테이블은 모두 RLS를 켜고 anon/authenticated 직접 접근과 RPC 실행을 회수한다. service-role은 서버에만 있다. 일반 회원 탈퇴는 이름·휴대폰·비밀번호와 관심 입력을 정리하며 UUID로 연결된 정산 이력은 남긴다. 기존 FC 탈퇴도 새 참조가 막지 않는다.

현재는 로컬 구현이다. 공통 개인정보처리방침·보유기간·기존 FC의 추가 목적 동의, 소비자 비밀번호 재설정, 실제 SMS·제휴 계약과 외부 구매 시스템은 출시 전 준비가 필요하다. 운영 DB·Edge·앱 배포와 실제 기기 검증은 이 구현의 로컬 검증과 구분한다.
